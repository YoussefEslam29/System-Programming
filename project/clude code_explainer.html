What does the Preprocessor do?
Before Pass 1 can do any real work, the raw assembly text file must be cleaned up. The Preprocessor's job is to take the raw lines of in.txt and convert them into structured objects that the rest of the assembler can work with easily.

Why separate this step? Assembly files contain messy content: inline comments, blank lines, variable whitespace. By cleaning all of that in one place first, Pass 1 can focus purely on logic without worrying about formatting.

The ParsedLine dataclass
📄 Lines 1–17 — imports + ParsedLine definition ▼
from dataclasses import field, dataclass from typing import Optional @dataclass class ParsedLine: line_no: int first: str second: Optional[str] = field(default=None) third: Optional[str] = field(default=None) @property def number_of_parts(self) -> int: return ( (self.first is not None) + (self.second is not None) + (self.third is not None) )
  • Line 1
    from dataclasses import field, dataclass — Python's dataclass decorator automatically generates boilerplate like __init__ and __repr__ so you don't have to write them manually. field lets you customise individual attributes, e.g. setting default values.
  • Line 2
    from typing import Optional — Optional[str] means the value can be a string or None. It's exactly equivalent to writing str | None. Used here because second and third fields won't always exist.
  • Line 4 @dataclass
    The @dataclass decorator tells Python: "automatically build an __init__ that takes line_no, first, second, third as constructor parameters." Without it, we'd need to write all that manually.
  • Line 6 line_no
    Stores the original line number from the source file. This is crucial for error messages — when the TA's auto-grader reports an error, it needs to say which line caused it.
  • Line 7 first
    first is always present (no default = required). In assembly, this is the first whitespace-separated token of a line. It could be a label (e.g. ALPHA), a mnemonic (e.g. LDA), or a directive (e.g. START).
  • Line 8 second
    second defaults to None if the line has fewer than 2 tokens. This is the second field — could be a mnemonic (if first was a label) or an operand (if first was a mnemonic).
  • Line 9 third
    third is the operand when a full label + mnemonic + operand triple is present. e.g. for ALPHA LDA BETA, first=ALPHA, second=LDA, third=BETA.
  • Lines 11–17
    The @property number_of_parts counts how many of the three fields are non-None. The trick: (self.first is not None) evaluates to the integer 1 (True) or 0 (False) in Python. Summing them gives 1, 2, or 3. Pass 1 uses this to decide if a line has a label, mnemonic-only, or mnemonic+operand.

The process() method — line by line
This is the core cleaning loop. It iterates over every raw string from in.txt and decides what to keep.
⚙️ process() — full breakdown ▼
def process(self, input_lines: list[str]) -> list[ParsedLine]: result = [] for i, line in enumerate(input_lines): line = line.strip() if "." in line: dot_idx = line.find(" .") if dot_idx != -1: line = line[:dot_idx] if line.lstrip().startswith("."): continue split_line = line.split() if not split_line: continue new_parsed_line = ParsedLine( line_no=i, first=split_line[0], second=split_line[1] if len(split_line) > 1 else None, third=split_line[2] if len(split_line) > 2 else None, ) result.append(new_parsed_line) self.parsed_lines = result return result
  • result = []
    A local accumulator list. We build it up during the loop and return it at the end. It's separate from self.parsed_lines so we can assign the whole result atomically on the last line (not one-by-one as we go).
  • enumerate()
    enumerate(input_lines) gives us both the index i (0-based line number) and the line string together. Without enumerate, we'd need a separate counter variable.
  • line.strip()
    Removes leading and trailing whitespace (spaces, tabs, newlines). This handles Windows \r\n line endings and any accidental indentation at the start of lines.
  • if "." in line
    SIC/XE uses . as the comment character. This block only runs if there's any dot at all on the line — an optimisation to avoid running comment logic on every single line.
  • line.find(" .")
    Searches for a space followed by a dot — this pattern marks an inline comment appended after code: LDA ALPHA . load accumulator. If found, line = line[:dot_idx] chops everything from that point onward, keeping only the code part.
  • lstrip().startswith(".")
    After removing inline comments, check if what remains (after stripping leading spaces) starts with a dot. If yes, the entire line is a comment line — skip it with continue.
  • line.split()
    str.split() with no argument splits on any whitespace (spaces, multiple spaces, tabs) and discards empties. So "ALPHA LDA BETA" → ["ALPHA", "LDA", "BETA"]. Much more robust than splitting on a single space.
  • if not split_line
    If the line was all whitespace or empty, split() returns an empty list. if not [] is True, so we skip it with continue. This handles blank lines between instructions.
  • ParsedLine(...)
    Constructs the structured object. first is always split_line[0]. second and third use conditional expressions: split_line[1] if len(split_line) > 1 else None — avoids IndexError when the list is short.
  • self.parsed_lines = result
    Saves the finished list onto the instance so export_to_file() can access it later without being passed the data explicitly.
⚠️
TA gotcha: The preprocessor does not know whether first is a label or a mnemonic — it just blindly picks the first token. It is Pass 1's job to figure that out by checking whether first matches a known opcode/directive.

export_to_file() — writing the intermediate file
💾 export_to_file() — breakdown ▼
def export_to_file(self, output_path: str) -> None: header = f"{'Line':<8}{'First':<12}{'Second':<12}{'Third'}" separator = "-" * 45 try: with open(output_path, "w") as f: f.write(header + "\n") f.write(separator + "\n") for line in self.parsed_lines: l_no = str(line.line_no) lbl = line.first or "" opc = line.second or "" opr = line.third or "" formatted_row = f"{l_no:<8}{lbl:<12}{opc:<12}{opr}" f.write(formatted_row.rstrip() + "\n") except IOError as e: print(f"Failed to write export file: {e}")
  • f-string :<8
    {'Line':<8} is an f-string format spec meaning: left-align the string and pad it to 8 characters wide with spaces. This creates aligned columns in the output file — important for readability and for automated parsers that expect fixed-width fields.
  • line.first or ""
    line.first or "" — if first is None or empty, use an empty string instead. Prevents None from being printed literally in the file.
  • .rstrip()
    Removes trailing spaces from each row before writing. Without this, rows with empty second/third would have trailing whitespace — which some diff tools and auto-graders flag as errors.
  • except IOError
    Wraps the file operation in a try/except. If the file can't be created (e.g. permissions issue, invalid path), it prints a helpful message instead of crashing the whole assembler.

Class-level constants
📌 _USER_BLOCKS and _USE_BLOCK_MAP ▼
class AssemblerPassOne: _USER_BLOCKS: tuple[MemoryBlock, ...] = ( MemoryBlock.DEFAULT, MemoryBlock.DEFAULTB, MemoryBlock.CDATA, MemoryBlock.CBLKS, ) _USE_BLOCK_MAP: dict[str, MemoryBlock] = { MemoryBlock.DEFAULT.value: MemoryBlock.DEFAULT, MemoryBlock.DEFAULTB.value: MemoryBlock.DEFAULTB, MemoryBlock.CDATA.value: MemoryBlock.CDATA, MemoryBlock.CBLKS.value: MemoryBlock.CBLKS, }
  • _USER_BLOCKS
    A tuple of the four blocks the user can switch into with a USE directive. Notice POOL is absent — users cannot write USE POOL; it is assembler-managed only. Being a class variable (not instance variable) means it's shared across all instances and defined once.
  • Underscore prefix _
    The leading underscore on _USER_BLOCKS and _USE_BLOCK_MAP is a Python convention meaning "this is intended to be private / internal." It's not enforced by the language but signals to other developers not to access these directly from outside the class.
  • _USE_BLOCK_MAP
    Maps the string name (e.g. "DEFAULT") to the enum value (MemoryBlock.DEFAULT). When the assembler sees USE CDATA, it looks up "CDATA" in this dict. If it's not found, it's an UnidentifiedBlockNameError per the spec.
  • .value
    MemoryBlock.DEFAULT.value gives the string representation of the enum, e.g. "DEFAULT". This is what comes from the assembly source file, so the dict key must be the string form.

__init__ — all state variables explained
🧠 Every instance variable and why it exists ▼
def __init__(self) -> None: # --- Location Counters (one per block) --- self.default_block_loc = 0 self.default_b_block_loc = 0 self.cdata_block_loc = 0 self.cblocks_block_loc = 0 self.pool_block_loc = 0 # --- Symbol Tables (one per block) --- self.default_block_symtab: dict[str, int] = {} self.default_b_block_symtab: dict[str, int] = {} self.cdata_block_symtab: dict[str, int] = {} self.cblocks_block_symtab: dict[str, int] = {} self.pool_block_symtab: dict[str, int] = {} # --- Assembled instruction list --- self.instructions: list[AssemblyInstruction] = [] self.start_address = 0 self.program_name = "" # --- POOL management --- self._pending_literals: list[str] = [] self._pending_literals_set: set[str] = set() self._pool_anchor_block: Optional[MemoryBlock] = None
  • 5 loc counters
    Each block gets its own integer location counter, all starting at 0. As instructions are processed, the counter for the currently active block advances by the instruction's byte size. They are kept separate because the blocks are laid out independently in memory.
  • 5 symtabs
    Each block has its own dict[str, int] — label name → LC value. Keeping them separate per block allows the assembler to correctly scope symbols and detect if the same label appears in two different blocks (which is a DuplicateSymbolError).
  • self.instructions
    A list of AssemblyInstruction objects built up during Pass 1. Each object stores the parsed line plus the block and LC assigned to it. This list is later used by Pass 2 and by export_intermediate_table().
  • _pending_literals
    A list of &-operand strings seen so far but not yet assigned a POOL address. The list preserves insertion order (important for reproducible output).
  • _pending_literals_set
    A set of the same literals. Sets have O(1) lookup, so checking "have I seen this literal before?" is instant. The list is for order; the set is for speed. They are always kept in sync.
  • _pool_anchor_block
    Records which block was active when the first & operand was encountered. Per the spec: "the position of the POOL block within the final memory layout is determined by the point at which the first & operand is encountered." This variable captures that point.

Block helper methods — the match/case trio
Rather than writing if block == CDATA: self.cdata_block_loc = ... everywhere, three helper methods centralise all block-routing logic.
🔀 _block_symtab, _get_block_loc, _set_block_loc ▼
def _block_symtab(self, block: MemoryBlock) -> dict[str, int]: match block: case MemoryBlock.DEFAULT: return self.default_block_symtab case MemoryBlock.DEFAULTB: return self.default_b_block_symtab case MemoryBlock.CDATA: return self.cdata_block_symtab case MemoryBlock.CBLKS: return self.cblocks_block_symtab case MemoryBlock.POOL: return self.pool_block_symtab case _: raise ValueError(...) def _get_block_loc(self, block) -> int: # same match pattern def _set_block_loc(self, block, value: int) -> None: # same + assigns
  • match/case
    Python 3.10+ structural pattern matching. match block: is like a type-safe switch statement. Each case MemoryBlock.X: matches exactly one enum value. case _: is the catch-all (default) — if an unknown block is passed, it raises ValueError immediately rather than silently doing nothing.
  • Why 3 methods?
    _block_symtab: given a block enum, returns its dict (read + write via the reference). _get_block_loc: returns the current LC integer for a block. _set_block_loc: writes a new LC integer. This design means all the rest of Pass 1 just calls _get_block_loc(block) and _set_block_loc(block, new_val) — never touches the raw attributes directly.
  • case _:
    The wildcard. If someone passes a MemoryBlock value that isn't handled above — which shouldn't happen in correct code — the ValueError acts as a safety net / defensive programming. Better to crash loudly than to silently corrupt state.
💡
Design insight: All three methods follow the same match block: pattern. This is called a dispatch table pattern — instead of scattering if/elif chains around the codebase, block routing is centralised here. When you add a new block, you only change these three methods.
🔒 _resolve_use_block — validates USE operands ▼
def _resolve_use_block( self, operand: Optional[str], program_counter: int, line_no: int ) -> MemoryBlock: if operand is None: return MemoryBlock.DEFAULT block = self._USE_BLOCK_MAP.get(operand.upper()) if block is None: expected = ", ".join(self._USE_BLOCK_MAP) raise UnidentifiedBlockNameError( f"Unidentified Block Name: '{operand}'. Expected one of {expected}.", program_counter, line_no, ) return block
  • operand is None
    A bare USE with no operand means "switch back to DEFAULT." This matches the SIC/XE convention where USE alone resets the active block.
  • operand.upper()
    Normalises the operand to uppercase before looking it up. This makes use cdata work the same as USE CDATA — case-insensitive matching, more robust.
  • .get() returns None
    dict.get(key) returns None (not KeyError) if the key doesn't exist. So if block is None, the operand wasn't one of the four valid names — this is the UnidentifiedBlockNameError required by the spec.
  • ", ".join(...)
    Builds a human-readable list of valid block names for the error message: "DEFAULT, DEFAULTB, CDATA, CBLKS". Makes the error message helpful for debugging.

Symbol management methods
🔍 _lookup_symbol, _lookup_symbol_entry, _add_symbol ▼
def _lookup_symbol(self, symbol: str) -> Optional[int]: for block in (*self._USER_BLOCKS, MemoryBlock.POOL): symtab = self._block_symtab(block) if symbol in symtab: return symtab[symbol] return None def _lookup_symbol_entry(self, symbol: str) -> Optional[tuple[MemoryBlock, int]]: for block in (*self._USER_BLOCKS, MemoryBlock.POOL): symtab = self._block_symtab(block) if symbol in symtab: return block, symtab[symbol] return None def _add_symbol(self, symbol, block, value, program_counter, line_no) -> None: if self._lookup_symbol_entry(symbol) is not None: raise DuplicateSymbolError(...) self._block_symtab(block)[symbol] = value
  • *self._USER_BLOCKS
    The * unpacks the tuple into the for-loop iterable. Combined with MemoryBlock.POOL added at the end, this searches all 5 blocks in order: DEFAULT → DEFAULTB → CDATA → CBLKS → POOL. The loop stops at the first match.
  • Two lookup methods
    _lookup_symbol returns just the integer LC (useful when you only care about the address). _lookup_symbol_entry returns (block, LC) as a tuple (useful when you also need to know which block the symbol is in, e.g. for duplicate detection).
  • _add_symbol
    Before adding a symbol, it calls _lookup_symbol_entry to check if that symbol already exists anywhere across all blocks. If it does → DuplicateSymbolError (required by spec). If not → writes symtab[symbol] = value into the correct block's dict.
⚠️
Important: Symbols are checked globally across ALL blocks for duplicates, even if they're in different blocks. Two labels with the same name in different blocks is still an error.

Expression evaluation — _try_parse_int, _resolve_term, _evaluate_expression
🧮 EQU expression evaluator breakdown ▼
def _try_parse_int(self, token: str) -> Optional[int]: cleaned = token.strip() if not cleaned: return None try: return int(cleaned, 0) except ValueError: return None def _resolve_term(self, term, current_loc, line_no) -> int: cleaned = term.strip() while cleaned.startswith(("#", "@")): cleaned = cleaned[1:] if cleaned.endswith(",X"): cleaned = cleaned[:-2] if cleaned == "*": return current_loc parsed_number = self._try_parse_int(cleaned) if parsed_number is not None: return parsed_number symbol_value = self._lookup_symbol(cleaned) if symbol_value is not None: return symbol_value raise InvalidDirectiveOperandError(...) def _evaluate_expression(self, expr, current_loc, line_no) -> int: expression = expr.replace(" ", "") plus_idx = expression.find("+", 1) minus_idx = expression.find("-", 1) # find first operator ... if op_idx == -1: return self._resolve_term(expression, ...) lhs = expression[:op_idx] rhs = expression[op_idx + 1:] return left_value + right_value if operator == "+" else left_value - right_value
  • int(cleaned, 0)
    The second argument 0 means "auto-detect base." So 0xFF → 255, 0b101 → 5, 010 → 8 (octal), bare digits → decimal. All numeric formats work automatically.
  • strip #, @, ,X
    Before resolving a term in an expression (like for EQU), addressing-mode prefixes must be stripped: # (immediate), @ (indirect), ,X (indexed). The while loop handles multiple stacked prefixes if present.
  • cleaned == "*"
    In SIC/XE, * means "current location counter." So EQU * assigns the label the current LC value — used to define equates relative to the current position.
  • find("+", 1)
    Starts searching for + from index 1 (not 0). Why? To avoid treating a leading + sign on a number as a binary operator. Same reasoning for -.
  • op_idx == -1
    If neither + nor - was found, the expression is just a single term (no arithmetic). Call _resolve_term directly and return.
  • lhs / rhs split
    Splits at the operator position: expression[:op_idx] = left side, expression[op_idx+1:] = right side. Each side is resolved via _resolve_term independently, then the results are added or subtracted. Supports expressions like END-START or ALPHA+3.

_byte_operand_size() and _literal_size()
📏 Calculating byte sizes for BYTE and & literals ▼
def _byte_operand_size(self, operand, program_counter, line_no) -> int: cleaned = operand.strip() if len(cleaned) >= 3 and cleaned[1] == "'" and cleaned.endswith("'"): kind = cleaned[0].upper() # 'C' or 'X' payload = cleaned[2:-1] # content between quotes if kind == "C": return len(payload) # 1 byte per char if kind == "X": return len(payload) // 2 # 2 hex digits = 1 byte def _literal_size(self, literal, program_counter, line_no) -> int: token = literal[1:] if literal.startswith("&") else literal # same C'/X' detection logic ... parsed_number = self._try_parse_int(token) if parsed_number is not None: return 3 # bare number → 1 WORD = 3 bytes
  • cleaned[1] == "'"
    Checks that the second character is a single quote. Combined with endswith("'"), this confirms the format is X'...' or C'...'. The length check >= 3 ensures there's at least a type char, two quotes, and possibly content.
  • C → len(payload)
    For character constants like C'HELLO', each ASCII character is exactly 1 byte. So C'HELLO' = 5 bytes.
  • X → len // 2
    For hex constants like X'FF2A', every 2 hex digits = 1 byte. So X'FF2A' = 2 bytes. Integer division // handles this. If the hex string has odd length, it raises an error (validated above).
  • literal[1:]
    In _literal_size, the & prefix is stripped before analysing the format. &X'10' → X'10', then the same C'/X' logic applies.
  • bare number → 3
    If the literal is just a number (no C' or X' wrapper), it's treated as a WORD value — 3 bytes, since SIC/XE words are 3 bytes wide.

POOL management — _collect_literals & _flush_literal_pool
This is the heart of what makes this assembler "modified" SIC/XE. The POOL block is built automatically, invisibly, during Pass 1.
🏊 Full POOL logic explained ▼
def _collect_literals(self, operand: Optional[str], block: MemoryBlock) -> None: if operand is None: return for raw in operand.split(","): token = raw.strip() if not token.startswith("&"): continue if self._pool_anchor_block is None: self._pool_anchor_block = block # record where POOL "belongs" if token in self.pool_block_symtab or token in self._pending_literals_set: continue # already seen — skip duplicate self._pending_literals.append(token) self._pending_literals_set.add(token) def _flush_literal_pool(self, line_no: int) -> None: for literal in self._pending_literals: self.pool_block_symtab[literal] = self.pool_block_loc self.pool_block_loc += self._literal_size(literal, self.pool_block_loc, line_no) self._pending_literals.clear() self._pending_literals_set.clear()
  • operand.split(",")
    Splits on comma to handle multiple operands like &X'10',&X'20' in one field. Each sub-token is checked independently.
  • startswith("&")
    Only tokens beginning with & are POOL literals. Regular operands are ignored here.
  • _pool_anchor_block
    Set only once — the first time a & is encountered. Stores the currently active block. Per the spec, this determines where in memory the POOL block is positioned relative to the other blocks.
  • Duplicate check
    Checks both pool_block_symtab (already flushed) AND _pending_literals_set (waiting to flush). If &X'10' appears twice in the source, it gets only one POOL entry — same address reused.
  • _pending vs symtab
    Literals accumulate in _pending_literals during parsing. They are only committed to pool_block_symtab when _flush_literal_pool is called. The flush happens at END directive (or at end of file as a fallback).
  • flush — assign LC then advance
    For each pending literal: first record its address (pool_block_symtab[literal] = pool_block_loc), then advance the POOL LC by the literal's byte size. Order matters — the assignment must happen before the advance.
  • .clear()
    After flushing, both the list and set are cleared. This allows _flush_literal_pool to be called multiple times safely (e.g. at each LTORG if you had one, or just once at END).
💡
Why pending + set? The list preserves order (so PoolTable.txt output is deterministic). The set gives O(1) duplicate detection. If you only used the list, you'd need O(n) linear scan for every new literal — slow for large programs.

📋 Full directive dispatch logic ▼
def _process_directive_pass_one(self, instruction, block_for_line, line_loc, line_no, current_block): directive = instruction.directive.upper() if instruction.label is not None: self._add_symbol(instruction.label, block_for_line, line_loc, ...) self._collect_literals(instruction.operand, block_for_line) if directive == "USE": return self._resolve_use_block(instruction.operand, ...) elif directive == "WORD": self._set_block_loc(block_for_line, line_loc + 3) elif directive == "RESW": words = self._parse_required_non_negative_operand(...) self._set_block_loc(block_for_line, line_loc + (3 * words)) elif directive == "RESB": bytes_count = self._parse_required_non_negative_operand(...) self._set_block_loc(block_for_line, line_loc + bytes_count) elif directive == "BYTE": byte_size = self._byte_operand_size(instruction.operand, ...) self._set_block_loc(block_for_line, line_loc + byte_size) elif directive == "END": self._flush_literal_pool(line_no) return current_block
  • directive.upper()
    Normalises directive name to uppercase. All comparisons below use uppercase strings, so both WORD and word in source will match.
  • Label registration first
    If the directive has a label (e.g. BUFFER RESB 256), that label is added to the symbol table at the current LC before advancing the LC. The label points to the start of the reserved area.
  • _collect_literals always
    Even directives can have &-prefixed operands (edge case). Calling _collect_literals here ensures those are captured regardless of which directive it is.
  • USE returns new block
    USE is the only directive that changes the active block, so it returns the new MemoryBlock value. All other directives return current_block unchanged (the block stays the same).
  • WORD → +3
    WORD always reserves exactly 3 bytes (one SIC/XE word). LC advances by 3.
  • RESW → 3 × n
    RESW n reserves n words = 3n bytes. No object code is generated — this just advances the LC to mark the space as occupied.
  • RESB → n
    RESB n reserves n bytes. Operand is validated to be a non-negative integer.
  • BYTE → _byte_operand_size
    Size depends on the operand format (C' vs X') so delegated to _byte_operand_size().
  • END → flush pool
    When END is encountered, all pending literals are finally committed to the POOL block symtab via _flush_literal_pool(). This is the main flush trigger.

_parse_instruction() — the critical ambiguity resolver
This is one of the most important methods. Assembly lines are ambiguous — "ALPHA LDA" could mean label=ALPHA mnemonic=LDA, or mnemonic=ALPHA operand=LDA. This method resolves that ambiguity.
🧩 Full parse logic ▼
def _parse_instruction(self, line: ParsedLine, current_block_loc=0): if line.number_of_parts == 1: mnemonic = line.first # e.g. RSUB (no label, no operand) elif line.number_of_parts == 2: if is_supported(line.first): # e.g. LDA ALPHA → mnemonic+operand mnemonic = line.first operand = line.second elif is_supported(line.second): # e.g. ALPHA LDA → label+mnemonic label = line.first mnemonic = line.second else: raise InvalidMnemonicOrDirective(...) else: # 3 parts: label + mnemonic + operand label = line.first mnemonic = line.second operand = line.third # Format detection + object construction if is_format4(mnemonic): return Format4Instruction(..., size=4) if opcode_info.fmt == InstructionFormat.FORMAT_1: return Format1Instruction(..., size=1) if opcode_info.fmt == InstructionFormat.FORMAT_2: return Format2Instruction(..., size=2) if opcode_info.fmt == InstructionFormat.FORMAT_3: return Format3Instruction(..., size=3)
  • number_of_parts
    Uses the number_of_parts property from ParsedLine to decide which parsing path to take. 1 part = mnemonic only. 2 parts = ambiguous. 3 parts = always label+mnemonic+operand.
  • is_supported()
    The key disambiguation function. It checks whether a string matches any known opcode or directive. If line.first is a known opcode (e.g. LDA), then line.first is the mnemonic, not a label.
  • 2-part ambiguity
    A two-token line could be either MNEMONIC OPERAND (e.g. LDA ALPHA) or LABEL MNEMONIC (e.g. ALPHA RSUB). is_supported is called on the first token first. If it's not a known opcode, the second token must be the mnemonic.
  • is_format4()
    Checks if the mnemonic starts with + (e.g. +JSUB). Format 4 instructions are always 4 bytes regardless of what the OPTAB says for the base mnemonic.
  • Format objects
    Each format gets its own class: Format1Instruction (size=1), Format2Instruction (size=2), Format3Instruction (size=3), Format4Instruction (size=4). The size is baked in at construction so the rest of Pass 1 just reads instruction.size without caring about format.
⚠️
TA likely question: "How do you know if the first token on a line is a label or a mnemonic?" Answer: you call is_supported() on it — if it's in the opcode/directive table, it's a mnemonic. If not, it must be a label.

process_pass_one() — the main loop
This is the entry point that orchestrates everything. It loops over every ParsedLine and routes it to the correct handler.

def process_pass_one(self, parsed_lines: list[ParsedLine]) -> None: current_block = MemoryBlock.DEFAULT for line in parsed_lines: current_block_loc = self._get_block_loc(current_block) instruction = self._parse_instruction(line, current_block_loc) if self._is_start_directive(instruction): current_block = self._handle_start_directive( cast(DirectiveInstruction, instruction), line.line_no ) self.instructions.append(instruction) continue block_for_line = current_block line_loc = self._get_block_loc(block_for_line) self._set_instruction_location(instruction, block_for_line, line_loc) if isinstance(instruction, DirectiveInstruction): current_block = self._process_directive_pass_one(...) else: self._process_machine_instruction_pass_one(...) self.instructions.append(instruction) if self._pending_literals: fallback_line_no = parsed_lines[-1].line_no if parsed_lines else 0 self._flush_literal_pool(fallback_line_no)
  • current_block
    The loop variable tracking which block is currently active. Starts as MemoryBlock.DEFAULT. Updated whenever a USE directive is processed. All LC reads and writes use this variable.
  • _get_block_loc(current_block)
    Gets the LC of the current block before processing the line. This LC becomes the instruction's location counter value.
  • _parse_instruction()
    Converts the raw ParsedLine tokens into a typed AssemblyInstruction object with known size and format. If the mnemonic is unrecognised, this raises InvalidMnemonicOrDirective.
  • START handled separately
    START is special — it must set the DEFAULT LC before anything else is processed. It's checked first and handled with _handle_start_directive, then continue skips the rest of the loop body for that line.
  • cast(DirectiveInstruction)
    cast() from the typing module is purely for type-checking tools (like mypy). It doesn't change runtime behaviour. It tells the type checker "I know this is a DirectiveInstruction" so it doesn't complain about the attribute access.
  • _set_instruction_location
    Stamps the instruction object with its block and LC. This permanently records where in memory this instruction lives — used later by Pass 2 and the intermediate file export.
  • isinstance check
    Dispatches to either _process_directive_pass_one or _process_machine_instruction_pass_one. Directives need extra handling (USE switches block, WORD/RESW/RESB advance LC differently). Machine instructions all follow the same pattern.
  • fallback flush
    After the loop, if any literals are still pending (i.e. the file had no END directive), they are flushed anyway. This prevents pool entries from being silently lost if the source is malformed.

  • _USER_BLOCKS only
    export_symbol_table iterates _USER_BLOCKS — that's DEFAULT, DEFAULTB, CDATA, CBLKS. The POOL block is not included here because POOL has its own separate export_pool_table method, keeping the two outputs distinct as required by the spec.
  • loc:04X
    {loc:04X} formats the integer as hexadecimal, uppercase, minimum 4 digits wide, zero-padded. So address 255 → 00FF. This is the standard LC representation in SIC/XE assembler output.
  • loc:>10
    {loc:>10} formats as right-aligned decimal in 10 characters. The table shows both hex and decimal LC values side-by-side for debugging convenience.
  • safety flush
    export_pool_table calls _flush_literal_pool(0) if there are still pending literals. This is a defensive measure — if someone calls export without having run the full pass, it still produces correct output.
  • block_locs property
    A read-only property that returns a snapshot dict of all block LCs. Used by Pass 2 to know the final LC of each block (which determines total block sizes and memory layout). The dict comprehension builds it cleanly in one line.
