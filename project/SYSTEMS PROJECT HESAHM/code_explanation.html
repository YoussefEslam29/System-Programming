Detailed Code Explanation — preprocessor.py & pass_one.py Simplified

[!TIP] This document explains every single section of both files. The pass_one.py has been rewritten to be significantly simpler — 629 lines → ~250 lines — while doing exactly the same thing. Read this before your TA discussion. Key TA questions are at the end.

Big Picture: How the Assembler Works

This project implements a two-pass SIC/XE assembler with program block support. The pipeline is:

graph LR
    A["in.txt<br/>(SIC/XE source)"] --> B["Preprocessor<br/>(tokenize)"]
    B --> C["Pass One<br/>(assign addresses,<br/>build SYMTAB)"]
    C --> D["Pass Two<br/>(generate object code,<br/>HTME records)"]
  1. Preprocessor — reads raw text, strips comments, splits each line into tokens (label, mnemonic, operand)
  2. Pass One — walks through tokens, assigns a location counter (address) to every instruction, builds the symbol table (SYMTAB) and literal pool
  3. Pass Two — uses the symbol table from Pass One to generate actual machine object code

The number_of_parts Property

@property
def number_of_parts(self) -> int:
    return (
        (self.first  is not None)   # always 1
      + (self.second is not None)   # 1 if present, else 0
      + (self.third  is not None)   # 1 if present, else 0
    )

How it works: In Python, True == 1 and False == 0. Adding three booleans gives 1, 2, or 3.

Why it's needed: Pass One uses number_of_parts to decide how to interpret the tokens — is the first token a label or a mnemonic?

Part 2: pass_one.py — First Pass of the Assembler Simplified

Full file: pass_one.py

[!NOTE] This file was rewritten to be shorter and clearer. The biggest change: instead of 5 separate variables for location counters and 5 separate dicts for symbol tables (with 3 giant match/case blocks to access them), the new version uses two simple dictionaries: self._locs and self._symtabs.

2.1 What Pass One Does (Theory)

Pass One's job is to:

  1. Assign an address (location counter) to every instruction
  2. Build the symbol table (SYMTAB) — mapping every label to its address
  3. Handle program blocks (USE directive) — multiple memory regions
  4. Collect literals (&C'EOF', &X'0F') into a literal pool

It does NOT generate any machine code — that's Pass Two's job.

[!IMPORTANT] Why separate location counters per block? Each program block has its own independent address space. When you USE CDATA, the location counter for DEFAULT is "frozen" and the CDATA counter continues. When you USE DEFAULT again, you pick up where DEFAULT left off.

[!NOTE] Why both a list AND a set for pending literals? The list preserves insertion order (so literals appear in the pool in the order they were first used). The set provides O(1) duplicate checking (so we don't add the same literal twice).

2.5 Symbol Table Helpers

_lookup_symbol(symbol)

def _lookup_symbol(self, symbol: str) -> Optional[tuple[MemoryBlock, int]]:
    """Search every block's symtab for `symbol`. Return (block, address) or None."""
    for block in ALL_BLOCKS:
        if symbol in self._symtabs[block]:
            return block, self._symtabs[block][symbol]
    return None

Searches ALL five symbol tables for a symbol. Returns (block, address) if found, None otherwise.

Note: the old code had two separate methods (_lookup_symbol returning just an int, and _lookup_symbol_entry returning the tuple). Now it's merged into one.

_add_symbol(symbol, block, value, program_counter, line_no)

def _add_symbol(self, symbol: str, block: MemoryBlock, value: int,
                program_counter: int, line_no: int) -> None:
    """Insert a symbol; raise DuplicateSymbolError if it already exists anywhere."""
    if self._lookup_symbol(symbol) is not None:
        raise DuplicateSymbolError(
            f"Duplicate symbol definition for '{symbol}'", program_counter, line_no)
    self._symtabs[block][symbol] = value
  1. Check for duplicates across ALL blocks — a symbol can only be defined once in the entire program.
  2. If not a duplicate, add it to the symbol table of the specified block.

[!WARNING] Duplicate symbols are an assembler error. If your source has ALPHA WORD 5 defined twice anywhere in the program, this raises DuplicateSymbolError.

2.6 Expression Evaluation

These methods handle operands that can be numbers, symbols, or simple expressions like ALPHA+3.

_try_parse_int(token)

def _try_parse_int(self, token: str) -> Optional[int]:
    """Try to parse a string as an integer. Return None on failure."""
    try:
        return int(token.strip(), 0)   # base 0 = auto-detect: 0x=hex, 0o=octal, 0b=binary
    except (ValueError, TypeError):
        return None

int(x, 0) is clever — it auto-detects the base from prefixes like 0x1A (hex), 0o17 (octal), 0b1010 (binary), or plain decimal.

_resolve_term(term, current_loc, line_no)

def _resolve_term(self, term: str, current_loc: int, line_no: int) -> int:
    """Resolve ONE operand token to a numeric value."""
    clean = term.strip().lstrip("#@")   # strip addressing-mode prefixes (# = immediate, @ = indirect)
    if clean.endswith(",X"):
        clean = clean[:-2]              # strip indexed-addressing suffix
    if clean == "*":
        return current_loc              # * means "current location counter"

    num = self._try_parse_int(clean)
    if num is not None:
        return num

    entry = self._lookup_symbol(clean)
    if entry is not None:
        return entry[1]                 # return just the address part

    raise InvalidDirectiveOperandError(
        f"Unable to resolve operand term '{term}'", current_loc, line_no)

Resolves a single term to a numeric value:

  1. Strip SIC/XE addressing prefixes: # (immediate), @ (indirect)
  2. Strip ,X (indexed addressing)
  3. * → current location counter value
  4. Try parsing as a number
  5. Try looking up as a symbol in SYMTAB
  6. If all fail → error

_evaluate_expression(expr, current_loc, line_no)

def _evaluate_expression(self, expr: str, current_loc: int, line_no: int) -> int:
    """Evaluate a simple expression like 'BUFEND-BUFFER' or 'LEN+3'."""
    s = expr.replace(" ", "")
    if not s:
        raise InvalidDirectiveOperandError("Empty directive operand", current_loc, line_no)

    # find the first '+' or '-' that is NOT at position 0 (position 0 could be a sign)
    for i in range(1, len(s)):
        if s[i] in "+-":
            left  = self._resolve_term(s[:i],    current_loc, line_no)
            right = self._resolve_term(s[i + 1:], current_loc, line_no)
            return left + right if s[i] == "+" else left - right

    # no operator found — the whole thing is a single term
    return self._resolve_term(s, current_loc, line_no)

Handles simple two-term expressions like ALPHA+3 or BETA-1.

[!NOTE] This only supports one operator (no chained expressions like A+B+C). This is sufficient for SIC/XE.

_require_non_negative(operand, current_loc, line_no, directive)

def _require_non_negative(self, operand: Optional[str], current_loc: int,
                          line_no: int, directive: str) -> int:
    """Parse an operand that must be present and non-negative."""
    if operand is None:
        raise InvalidDirectiveOperandError(
            f"Directive '{directive}' requires an operand", current_loc, line_no)
    value = self._evaluate_expression(operand, current_loc, line_no)
    if value < 0:
        raise InvalidDirectiveOperandError(
            f"Directive '{directive}' requires a non-negative operand", current_loc, line_no)
    return value

Used by RESW and RESB — they need a positive integer to know how much space to reserve.

2.7 BYTE / Literal Size Calculation Simplified — shared helper

_data_constant_size(operand, pc, line_no, default_num_size, error_label)

def _data_constant_size(self, operand: str, pc: int, line_no: int,
                        default_num_size: int = 1,
                        error_label: str = "BYTE") -> int:
    """Compute the byte-size of a C'…', X'…', or numeric constant.
       default_num_size is 1 for BYTE operands, 3 for literals.
    """
    clean = operand.strip()
    if len(clean) >= 3 and clean[1] == "'" and clean.endswith("'"):
        kind, payload = clean[0].upper(), clean[2:-1]
        if kind == "C":
            return len(payload)            # C'EOF' = 3 bytes
        if kind == "X":
            if len(payload) % 2 != 0:
                raise InvalidDirectiveOperandError(
                    f"Hex {error_label} operand must contain an even number of digits", pc, line_no)
            return len(payload) // 2       # X'0F1A' = 2 bytes
    if self._try_parse_int(clean) is not None:
        return default_num_size            # plain number: 1 byte for BYTE, 3 for literals
    raise InvalidDirectiveOperandError(f"Unsupported {error_label} operand '{operand}'", pc, line_no)

This single helper is shared by both BYTE and literal size calculation — the old code duplicated this logic twice.

_byte_operand_size and _literal_size

def _byte_operand_size(self, operand: Optional[str], pc: int, line_no: int) -> int:
    if operand is None:
        raise InvalidDirectiveOperandError("Directive 'BYTE' requires an operand", pc, line_no)
    return self._data_constant_size(operand, pc, line_no, default_num_size=1, error_label="BYTE")

def _literal_size(self, literal: str, pc: int, line_no: int) -> int:
    token = literal.lstrip("&").strip()   # strip the & prefix
    return self._data_constant_size(token, pc, line_no, default_num_size=3, error_label="literal")

2.8 Literal Pool Management

_collect_literals(operand, block)

def _collect_literals(self, operand: Optional[str], block: MemoryBlock) -> None:
    """Scan the operand for '&'-prefixed literals and queue them for the pool."""
    if operand is None:
        return
    for raw in operand.split(","):
        token = raw.strip()
        if not token.startswith("&"):
            continue
        if self._pool_anchor_block is None:
            self._pool_anchor_block = block   # remember which block triggered first literal
        if token not in self._symtabs[MemoryBlock.POOL] and token not in self._pending_literals_set:
            self._pending_literals.append(token)
            self._pending_literals_set.add(token)

Called for every instruction. Scans the operand for literal references (tokens starting with &):

  • Splits by comma to handle indexed addressing like &X'0F',X
  • Records the first block that uses a literal (_pool_anchor_block) — Pass Two needs this to know where to place the literal pool
  • Adds new literals to the pending list (avoiding duplicates)

_flush_literal_pool(line_no)

def _flush_literal_pool(self, line_no: int) -> None:
    """Assign addresses to all pending literals and clear the queue."""
    pool_loc = self._locs[MemoryBlock.POOL]
    for lit in self._pending_literals:
        self._symtabs[MemoryBlock.POOL][lit] = pool_loc
        pool_loc += self._literal_size(lit, pool_loc, line_no)
    self._locs[MemoryBlock.POOL] = pool_loc
    self._pending_literals.clear()
    self._pending_literals_set.clear()

Assigns addresses to all pending literals:

  1. For each literal, record its address in the pool symtab
  2. Advance pool_loc by the literal's size
  3. Save the final value back to self._locs[MemoryBlock.POOL]
  4. Clear the pending lists

This is called when END is encountered (or at the very end of the program).

2.9 USE Block Resolution

def _resolve_use_block(self, operand: Optional[str], pc: int, line_no: int) -> MemoryBlock:
    """Return the MemoryBlock for a USE directive. Defaults to DEFAULT if no operand."""
    if operand is None:
        return MemoryBlock.DEFAULT
    block = USE_BLOCK_MAP.get(operand.upper())
    if block is None:
        raise UnidentifiedBlockNameError(
            f"Unidentified Block Name: '{operand}'. Expected one of {', '.join(USE_BLOCK_MAP)}.",
            pc, line_no)
    return block

What it does: When the assembler encounters USE CDATA, this method converts the string "CDATA" to MemoryBlock.CDATA.

  • If USE has no operand (just USE by itself), defaults back to MemoryBlock.DEFAULT.
  • If the operand is invalid (e.g., USE FOOBAR), throws an error listing valid block names.

2.10 Parsing a Source Line into an Instruction Object

def _parse_instruction(self, line: ParsedLine, current_loc: int = 0) -> AssemblyInstruction:
    """Turn a ParsedLine (1–3 fields) into the right AssemblyInstruction subclass."""
    label = operand = None

    if line.number_of_parts == 1:
        mnemonic = line.first                          # e.g., "RSUB"

    elif line.number_of_parts == 2:
        if is_supported(line.first):
            mnemonic, operand = line.first, line.second  # e.g., LDA #0
        elif is_supported(line.second):
            label, mnemonic = line.first, line.second    # e.g., FIRST RSUB
        else:
            raise InvalidMnemonicOrDirective(...)

    else:  # 3 parts — unambiguous
        label, mnemonic, operand = line.first, line.second, line.third  # e.g., ALPHA WORD 5

The 2-token disambiguation step is critical:

  • LDA ALPHA → first token (LDA) is a known mnemonic → mnemonic operand
  • FIRST RSUB → second token (RSUB) is a known mnemonic → label mnemonic

Building the Typed Instruction Object

    # Directives → DirectiveInstruction (size = 0)
    if is_directive(mnemonic):
        return DirectiveInstruction(parsed_line=line, size=0,
                                    label=label, directive=mnemonic, operand=operand)

    # Machine instructions → look up format, return the right class
    info = lookup_opcode(mnemonic)
    if info is not None:
        if is_format4(mnemonic):                          # starts with "+"
            return Format4Instruction(parsed_line=line, size=4,
                                      label=label, mnemonic=mnemonic, operand=operand)

        # Map format enum → (class, size, has_operand)
        fmt_map = {
            InstructionFormat.FORMAT_1: (Format1Instruction, 1, False),
            InstructionFormat.FORMAT_2: (Format2Instruction, 2, True),
            InstructionFormat.FORMAT_3: (Format3Instruction, 3, True),
        }
        cls, size, has_op = fmt_map[info.fmt]
        kwargs = dict(parsed_line=line, size=size, label=label, mnemonic=mnemonic)
        if has_op:
            kwargs["operand"] = operand
        return cls(**kwargs)

Decision tree:

  1. Is it a directive? → DirectiveInstruction (size = 0)
  2. Does it start with +? → Format4Instruction (size = 4)
  3. Look up in fmt_map → Format1 (1 byte), Format2 (2 bytes), or Format3 (3 bytes)

[!TIP] The fmt_map dictionary replaces 3 separate if opcode_info.fmt == blocks from the old code. Instead of repeating the same pattern three times, one dict lookup does the job.

2.11 Handle the START Directive

def _handle_start(self, instr: DirectiveInstruction, line_no: int) -> None:
    """Process START: set program name, starting address, and symbol."""
    self.start_address = int(instr.operand) if instr.operand else 0
    self.program_name  = instr.label or ""
    self._locs[MemoryBlock.DEFAULT] = self.start_address
    instr.block            = MemoryBlock.DEFAULT
    instr.location_counter = self.start_address
    if instr.label:
        self._add_symbol(instr.label, MemoryBlock.DEFAULT,
                         self.start_address, self.start_address, line_no)

For COPY START 0:

  1. Sets starting address to 0
  2. Saves program name as "COPY"
  3. Sets DEFAULT block's location counter to 0
  4. Adds COPY to the DEFAULT symbol table at address 0

2.12 Process One Directive (after START) Simplified

def _process_directive(self, instr: DirectiveInstruction, block: MemoryBlock,
                       loc: int, line_no: int, current_block: MemoryBlock) -> MemoryBlock:
    """Handle a directive, update location counter, return the (possibly changed) active block."""
    d = instr.directive.upper()

    if instr.label:
        self._add_symbol(instr.label, block, loc, loc, line_no)

    self._collect_literals(instr.operand, block)

    if   d == "USE":   return self._resolve_use_block(instr.operand, loc, line_no)
    elif d == "WORD":  self._locs[block] = loc + 3
    elif d == "RESW":  self._locs[block] = loc + 3 * self._require_non_negative(instr.operand, loc, line_no, "RESW")
    elif d == "RESB":  self._locs[block] = loc +     self._require_non_negative(instr.operand, loc, line_no, "RESB")
    elif d == "BYTE":  self._locs[block] = loc + self._byte_operand_size(instr.operand, loc, line_no)
    elif d == "END":   self._flush_literal_pool(line_no)

    return current_block

2.13 Process One Machine Instruction

def _process_machine(self, instr: AssemblyInstruction, block: MemoryBlock,
                     loc: int, line_no: int) -> None:
    label   = getattr(instr, "label",   None)
    operand = getattr(instr, "operand", None)
    if label:
        self._add_symbol(label, block, loc, loc, line_no)
    self._collect_literals(operand, block)
    self._locs[block] = loc + instr.size

For machine instructions (LDA, STA, CLEAR, +LDX, etc.):

  1. If it has a label → add to SYMTAB
  2. If its operand references a literal → collect it
  3. Advance the location counter by instr.size (1, 2, 3, or 4 bytes)

getattr(instr, "label", None) is used because the base class AssemblyInstruction doesn't always have label or operand fields — getattr safely returns None if the attribute doesn't exist.

2.14 The Main Loop — process_pass_one()

def process_pass_one(self, parsed_lines: list[ParsedLine]) -> None:
    """Run pass 1 over all parsed source lines."""
    current_block = MemoryBlock.DEFAULT         # start in DEFAULT block

    for line in parsed_lines:
        loc   = self._locs[current_block]       # get LC for the active block
        instr = self._parse_instruction(line, loc)

        # ── Special case: START ──
        if isinstance(instr, DirectiveInstruction) and instr.directive.upper() == "START":
            self._handle_start(instr, line.line_no)
            self.instructions.append(instr)
            continue

        # ── Stamp instruction with its block and address ──
        instr.block            = current_block
        instr.location_counter = loc

        # ── Dispatch to directive vs. machine processing ──
        if isinstance(instr, DirectiveInstruction):
            current_block = self._process_directive(
                instr, current_block, loc, line.line_no, current_block)
        else:
            self._process_machine(instr, current_block, loc, line.line_no)

        self.instructions.append(instr)

    # Flush any remaining literals (safety net if there was no END directive)
    if self._pending_literals:
        self._flush_literal_pool(parsed_lines[-1].line_no if parsed_lines else 0)

Step by step for each line:

  1. Read the current location counter for the active block
  2. Parse the line into a typed instruction object
  3. If it's START, handle it specially and move on
  4. Otherwise, stamp the instruction with its block + address
  5. If directive → process directive (may switch blocks, advance LC)
  6. If machine instruction → add label to SYMTAB, advance LC by instruction size
  7. Append to the instruction list

Potential TA Discussion Questions

Q1: Why is a two-pass assembler needed? Can't we do it in one pass?

A: Forward references. For example, LDB #BASEVAL is on line 6 but BASEVAL is defined on line 19. Pass One collects all labels and their addresses into SYMTAB first; Pass Two uses that table to resolve every reference. A one-pass assembler would need to backpatch, which is more complex.

Q2: What is the purpose of program blocks (USE directive)?

A: They allow logically separating code, data, and reserved storage while keeping them in one source file. Each block maintains its own location counter starting from 0. Pass Two calculates absolute addresses by deciding the final order of blocks and adding each block's base offset.

Q3: How does the preprocessor handle comments?

A: Two types: (1) full-line comments starting with . are skipped entirely with continue, (2) inline comments ( . pattern) are stripped from the end of the line before tokenization.

Q4: What's the difference between literals and immediate operands?

A: Immediate (#5) embeds the value directly in the instruction encoding. Literals (&C'EOF') allocate memory in the literal pool to store the value, and the instruction references that memory address.

Q5: How does _parse_instruction disambiguate 2-token lines?

A: It checks if the first token is a valid mnemonic/directive using is_supported(). If yes → mnemonic operand. If not, checks if the second token is valid → label mnemonic. If neither is valid → raises InvalidMnemonicOrDirective.

Q6: Why separate symbol tables per block?

A: Each block has its own address space starting from 0. A symbol's address is relative to its block. Pass Two calculates the absolute address by adding the block's starting offset (which is determined by the order the blocks are laid out in memory).

Q7: What happens if a symbol is defined twice?

A: _add_symbol first calls _lookup_symbol which searches ALL blocks. If the symbol is found anywhere — even in a different block — it raises DuplicateSymbolError. Labels must be globally unique across the entire program.

Q8: When is the literal pool flushed?

A: Primarily when END is encountered inside _process_directive. There is also a safety net at the end of process_pass_one() — if there are still unflushed literals after the loop (e.g., no END directive), they get flushed then.

Q9: What was the biggest simplification in the rewrite?

A: Replacing 5 separate location-counter variables + 5 separate symbol-table dicts + 3 giant match/case helper methods with two dictionaries: self._locs[block] and self._symtabs[block]. This eliminated ~200 lines of repetitive code while doing exactly the same thing.

Q10: What does getattr(instr, "label", None) do?

A: It safely reads the label attribute from an instruction, returning None if the attribute doesn't exist. This is needed because the base class AssemblyInstruction doesn't declare label or operand — only the subclasses do. Using getattr avoids an AttributeError.
